01 — What we are building

System overview

The NL2SQL engine accepts a plain English question, uses an LLM agent to call metadata tools, assembles precise schema context, generates SQL, validates it, executes it, and returns structured results — all without any hardcoded table knowledge.

Metadata layer

The source of truth. Stores table descriptions, column types, FK relationships, enum values, and vector embeddings for semantic search. Never queries a live DB in the hot path.

LLM agent loop

The controller drives a multi-turn tool-calling loop. The LLM picks which metadata tools to call, receives results, and iterates until it has enough context to generate accurate SQL.

04 — Tool definitions

The 6 LLM tool calls

These are the only functions the LLM can invoke. Every tool takes primitive types (strings, lists of strings) so they serialize cleanly as Anthropic tool schemas. The controller dispatches them; the model layer executes them.

find_relevant_tables
(query: str, top_k: int = 5)
→ list[TableMatch]
Semantic similarity search over table description embeddings. Returns the 3–5 most relevant tables for this query. This is always the first tool call.
Always called first
get_table_schema
(table_names: list[str])
→ SchemaContext
Returns column names, data types, nullability, PK/FK flags, and business descriptions for each requested table. Core input for SQL generation.
Called after find_relevant_tables
get_table_relationships
(table_names: list[str])
→ list[Relationship]
Returns FK edges, join keys, cardinality (1:N, M:N), and bridge tables between the specified tables. Critical for multi-table queries.
Called in parallel with get_schema
get_sample_values
(table: str, column: str)
→ list[str]
Returns up to 20 distinct values for a column. Resolves enum mismatches — e.g. user says "completed" but DB stores "COMPLETED". Essential for WHERE clauses.
Called when column looks like enum/status
get_query_examples
(query: str, top_k: int = 3)
→ list[Example]
Retrieves the most similar past (NL, SQL) pairs from the query log. Used for few-shot prompting — dramatically improves accuracy on repeated query patterns.
Called on complex or ambiguous queries
validate_sql
(sql: str, db_id: str)
→ ValidationResult
Dry-runs the SQL with EXPLAIN / LIMIT 0 against the target DB. Returns syntax errors, unknown column names, or permission issues before real execution.
Always called before execute()

06 — Reference implementation

Key code patterns

These are the canonical implementations each class must follow. Copy these patterns exactly — deviating from the interface contracts between layers is the most common source of regressions.

QueryController — the main pipeline

controller/query_controller.py Python 
class QueryController:
    def __init__(self, model: ModelFacade):
        self.model      = model
        self.parser     = IntentParser()
        self.orchestrator = ToolOrchestrator(model)
        self.generator  = SQLGenerator()
        self.validator  = SQLValidator()
        self.formatter  = ResultFormatter()

    async def handle(self, req: QueryRequest) -> QueryResponse:
        # 1. Parse intent from natural language
        intent = await self.parser.parse(req.nl_query)

        # 2. Run metadata tool calls to gather schema context
        context = await self.orchestrator.gather_context(intent)

        # 3. Generate SQL from intent + context
        sql = await self.generator.generate(intent, context)

        # 4. Validate before touching the DB — no exceptions
        self.validator.check(sql, req.db_id)

        # 5. Execute against the real database
        rows = await self.model.db.execute(sql, req.db_id)

        # 6. Format and return structured response
        return self.formatter.format(sql, rows, context, intent)

ToolOrchestrator — the agentic loop

controller/tool_orchestrator.py Python 
MAX_TOOL_ROUNDS = 5
TOOLS = [find_tables, get_schema, get_relationships,
         get_sample_values, get_examples]

class ToolOrchestrator:
    async def gather_context(self, intent: Intent) -> SchemaContext:
        messages = [{
            "role": "user",
            "content": build_context_prompt(intent)
        }]

        for _ in range(MAX_TOOL_ROUNDS):
            response = await llm.call(
                messages=messages,
                tools=TOOLS,
                model="claude-sonnet-4-20250514"
            )

            # LLM has enough context — stop the loop
            if response.stop_reason == "end_turn":
                break

            # Execute every tool call the LLM requested
            tool_results = []
            for call in response.tool_calls:
                result = await dispatch(call, self.model)
                tool_results.append({
                    "tool_call_id": call.id,
                    "content": result
                })

            messages.append({"role": "assistant", "content": response.content})
            messages.append({"role": "tool", "content": tool_results})

        return extract_context(messages)

ModelFacade — single interface for the controller

model/facade.py Python 
class ModelFacade:
    def __init__(self, settings: Settings):
        self.registry    = TableRegistry(settings.db_url)
        self.graph       = RelationshipGraph(settings.db_url)
        self.embeddings  = EmbeddingIndex()
        self.value_index = ValueStore(settings.db_url)
        self.query_log   = QueryLog(settings.log_db_url)
        self.db          = DatabaseConnector(settings.db_url)

    async def find_tables(self, query: str, top_k: int = 5):
        return self.embeddings.search(query, top_k)

    async def get_schema(self, tables: list[str]):
        return self.registry.get_columns(tables)

    async def get_relationships(self, tables: list[str]):
        return self.graph.get_paths(tables)

    async def get_sample_values(self, table: str, col: str):
        return self.value_index.get(table, col)

View — FastAPI routes

view/api/routes.py Python 
router = APIRouter()

@router.post("/query", response_model=QueryResponse)
async def query(
    req: QueryRequest,
    ctrl: QueryController = Depends(get_controller)
):
    try:
        return await ctrl.handle(req)
    except SQLValidationError as e:
        raise HTTPException(422, detail=str(e))
    except UnsafeQueryError as e:
        raise HTTPException(403, detail=str(e))
    except Exception:
        raise HTTPException(500, detail="Query pipeline failed")

07 — Coverage

Query scenarios to handle

These are the scenarios the engine must handle correctly. Build a golden test for each one. The tool call column shows which tool calls the LLM should make for that query type.

Query type Example Key tool calls
Single table Show all users created this month find_tables → get_schema
Multi-table join Orders with customer names and product titles find_tables → get_schema → get_relationships
Aggregation Total revenue per region last quarter find_tables → get_schema → glossary lookup
Enum filter Show me completed orders find_tables → get_schema → get_sample_values
Relative dates Users who signed up in the last 7 days find_tables → get_schema (date format hint)

Unsafe query Delete all test users SQLValidator blocks → 403 error
08 — Contracts

Non-negotiable rules

These are hard architectural contracts. Breaking any of them causes cascading failures that are difficult to debug and expensive to fix later.

✗
View never imports from model/. The view layer may only call methods on the controller. If you find yourself doing from model.registry import TableRegistry inside a route file, it is wrong.
✗
Model never calls the LLM. All LLM calls live in the controller layer (ToolOrchestrator, SQLGenerator). The model layer only reads and writes data.
✗
SQLValidator must run before every db.execute(). No exceptions, no flags, no bypasses. This is the safety gate that prevents destructive queries. Wire it directly into QueryController, not as an optional step.
!
Tool functions take only primitive types. Every tool argument must be a str, int, float, or list of those. No dataclasses, no Pydantic models. This is required for clean Anthropic tool schema serialization.
!
Controller uses ModelFacade, not individual model classes. The controller imports only ModelFacade. This is the seam that lets you swap storage backends without touching controller logic.
✓
Every query must be logged. Write (nl_query, generated_sql, execution_success, latency_ms) to QueryLog after every handle() call, even on failure. This data trains the few-shot retrieval that improves accuracy over time.
✓
Metadata sync must be idempotent. Running loader.sync() twice must produce the same result as running it once. New tables get added, removed tables get flagged, descriptions from metadata.yaml override introspected ones.
